# 독립 저장소 v0.1.0 기준

2026-11-23 · 현재 수치 실행 범위

## 기준선 결정

로컬 `main`의 `8192cf0923995e200185f271fba76b2387db9d67`을
`v0.1.0`으로 수용했다. `git cat-file -t refs/tags/v0.1.0`은
`tag`를 반환했고, 태그가 가리키는 커밋도 일치했다. 당시 작업 트리는
깨끗했고 수치 사례 10개, 회귀 테스트 7개, 결과 파일 재계산 대조를 확인했다.
수용 범위는 로컬 수치 재현이다.

| 증거 | 상태 |
| --- | --- |
| `window-results.json` | 이전 Colab 결과의 SHA-256과 바이트 보존. 기존 10개 사례 |
| `window-results-v2.json` | 자체 산술 모듈과 실행기로 재생성. 10개 사례 전체의 입력 해시·유리수 끝점·판정이 이전 Colab 기준과 일치 |
| `lean-extract-manifest.json` | 아카이브 조각 14개의 SHA-256 및 로컬 추출물 15개의 일치 항목을 기록 |
| `unit_test_receipt.json` | 별도 Proof Atlas 개발 환경의 역사적 13개 테스트. 그 패키지의 실행 가능한 소스는 이 작업 폴더에서 확인되지 않음 |
| 이번 Lean 검수 | 원본 바이트 대조 및 정적 소스 추적. proof-value closure, 커널 실행, 독립 운영자 재현은 미수행 |

[실행 명세](CROSS_REPO_WORKFLOW_AND_VERIFICATION_SPEC_ko.md)의 사례 누락 검수는
수치 실행이 다섯 건이었던 이전 스냅샷을 설명한다. 지금의 케이스 목록은
이전 Colab과 독립 구현 양쪽에 열 건 있으며, 삭제·변조 사례는
[회귀 검사](../tests/test_replay.py)에서 기각된다. 이전 파일의 이력은 보존했다.

MB-06은 과거와 비교 가능한 산술 사례다. NSRW와 TOE 계획은 연구 전이 문서에
남긴다. 새 저장소의 계산·회귀 검사는 두 저장소나 두 프로젝트의 Lean 환경에
접근하지 않고 실행한다.

원본 RH 선언의 직접 참조 추출은 [별도 검증 기록](PROOF_DEPENDENCY_PILOT_ko.md)에
기록한다. 이 작업은 고정된 v0.1.0 수치 기준선 이후의 검증이다.

## 후속 수용 기준

| 버전 | 수용 기준 |
| --- | --- |
| v0.1.0 | 열 가지 수치 사례에서 기존 실행의 입력 해시·유리수 경계·판정을 재현하고 회귀 검사를 통과한다. |
| v0.2.0 | 실제 Lean 정리의 elaborated type과 proof value에서 참조 선언을 따로 추출한다. 단순 import를 참조 간선으로 추가하지 않는지 대조한다. |
| v0.3.0 | 작은 부등식 하나를 고정된 Lean 환경에서 증명하고, 정확한 선언과 가정이 수치 결과에 어떻게 대응하는지 재현한다. |

`Classical.choice`가 증명 경로에 있는지는 공리 의존성 조사에서 기록한다.
수치 평가에 필요한 정의가 선택된 객체에 의존하는지는 별도로 확인한다.
후자의 경우, 예를 들어 NSRW MB08의 원본 cutoff에는 실제 선택 함수에
적용되는 정량 경계나 그와 동등한 평가 근거가 필요하다.
